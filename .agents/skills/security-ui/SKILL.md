# Security UI

Design for immediate comprehension.

A judge should understand:

WHAT IS PROTECTED?
WHAT ATTACKED IT?
WHAT DID THE AGENT TRY?
WHAT DID THE GATEWAY DO?
WHY WAS IT BLOCKED?

Avoid generic AI dashboard patterns.

Use:

- strong hierarchy
- dense but readable security telemetry
- live event streams
- execution traces
- policy visualization
- clear status indicators
- restrained animation
- purposeful motion

Main visual:

Agent
↓
Tool Request
↓
Gateway
↓
Policy
↓
Decision
↓
Tool

Blocked requests should have a visually unmistakable state.

Clicking an event should reveal the complete security decision.

Do not use decorative elements that do not communicate product functionality.
